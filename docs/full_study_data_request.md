# Full historical data request

This request implements the frozen protocol without inspecting final outcomes.
The machine-readable [export plan](../reports/full_market_request/full_export_plan.json)
and [16 annual liquidity windows](../reports/full_market_request/year_start_windows.csv)
are generated by `disclosure plan-full-export`.

## Population and dates

| Input | Required coverage and interpretation |
|---|---|
| Historical stock population | All eligible U.S. common stocks at each year start, 2010–2025, including securities that later delist |
| Listing and share classification | Dated intervals, source evidence and information-availability timestamps; no current-list substitution |
| CIK/security mapping | Historical security identifiers, share classes, effective start/end bounds, source and review evidence |
| Selection liquidity | Exactly 60 XNYS sessions preceding each January 1; earliest requested session is October 7, 2009 |
| Development filings | Acceptance years 2010–2021, plus predecessor filings from 2009 |
| Development returns | All exact control/label sessions; latest possible label session is February 2, 2022 |
| Final filings | Acceptance years 2022–2025, collected only after development prerequisites pass |
| Final returns | Separate sealed export; latest possible label session is February 3, 2026 |
| Prior controls | 60 sessions ending at each reference session's previous close, plus exact-date USD capitalization and historical industry |
| Benchmark | Daily value-weighted total market returns covering every label session, including after a stock's terminal event |

The 20-company parser pilot cannot supply this population. Its liquidity and
survival history do not establish which issuers would have been selected in
2010, 2011, or any other year. Selection keeps the most liquid eligible share
class per issuer, requires at least 40 valid liquidity observations, ranks by
mean dollar volume, and retains up to 500 issuers per year.

## Export bundles

1. **Population bundle:** historical listings, dated identity links and daily
   dollar volume. Use the normalized names and types in
   [historical_dataset.md](historical_dataset.md). Preserve actual vendor field
   definitions, units, query text, export time and release/version information.
2. **Development market bundle:** audited total returns, terminal-event flags,
   benchmark returns and dated capitalization/industry. Dividends and delisting
   returns must enter exactly once. Use [market_data_contract.md](market_data_contract.md)
   and the existing [CIZ staging workflow](crsp_staging.md).
3. **Final market bundle:** physically separate final-target inputs and label
   values. A data custodian can stage this independently; research commands
   require completed development prerequisites before opening final data.
4. **Evidence bundle:** exact source hashes, reviewable documents/rows, reviewed
   effective bounds and source availability. Associate every retained event
   with the evidence records prescribed by the dataset contract.

Do not replace historical timestamps with an assumption that a modern download
was available at the original forecast date. Record revised data and unsupported
availability explicitly. The SEC SGML acceptance timestamp is the documented
reference; actual dissemination timing remains a review requirement.
